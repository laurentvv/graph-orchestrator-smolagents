# 16 — learn-claude-code

## En-tête
- **Nom** : learn-claude-code (shareAI-lab/learn-claude-code)
- **Chemin** : `references/learn-claude-code/`
- **Type** : Cours didactique en 20 leçons qui déconstruit Claude Code en « harness engineering ». Aucune dépendance lourde, aucune prétention produit : le but est pédagogique.
- **Langage principal** : **Python natif** (25 fichiers `.py`, 0 TypeScript côté agent). Stack minimal : `anthropic` + `python-dotenv` + `pyyaml`. Le dossier `web/` (Next.js/React) est uniquement le site vitrine du cours, non pertinent.
- **Statistiques** : 20 leçons `s01_*` → `s20_*` (137 à 2119 lignes chacune) ; dossier `agents/` (13 fichiers consolidés, dont `s_full.py` 740 lignes capstone s01-s11) ; `skills/` (4 SKILL.md) ; `tests/` (4 fichiers unittest non triviaux) ; `docs/` (12 leçons × 3 langues, narratif) ; 449 fichiers au total dont 87 SVG (diagrammes).

## Synthèse
**C'est la référence la plus directement exploitable du dossier pour les briques transversales de l'orchestrateur** (hooks, compaction, error recovery, skill loading, task graph), et ce pour une raison simple : **contrairement à qm (TypeScript), tout est en Python natif** et le portage est quasi littéral. Le code est pédagogique mais **fonctionnel et testé** — chaque `code.py` est un agent qui tourne, et les tests valident des préoccupations réelles (ex. préservation des paires `tool_use`/`tool_result` lors de la compaction, ce qui est exactement notre futur middleware « Orphan Repair » de la Priorité 8).

La doctrine du dépôt (README) est en phase avec l'architecture du projet cible : *« Agency comes from the model. An agent product = model + harness. »* Le « harness » = Tools + Knowledge + Observation + Action + Permissions. Le projet cible suit déjà ce schéma (DSPy-Brains + smolagents-Hands + DuckDB + tools + checkpoints).

**Lacunes identifiées** (à combler ailleurs) : aucun anti-loop cryptographique (P3 → garder `crush`), aucune persistance DuckDB/claims-refutations (P6 Judge → garder `open-swe`), sandbox limitée à un deny-list (P8-bis → garder `qm`), pas de scopes multi-utilisateurs réels (P12 → `qm`). **Note de réutilisabilité globale : Haute.**

## Exclusions conscientes
- **`s14_cron_scheduler` (804 lignes), `s17_autonomous_agents` (813 lignes)** : scenarios multi-agents asynchrones (idle poll 60s, auto-claim). L'orchestrateur cible est synchrone (Routeur → Architect → Coders → Tester → Judge), pas une nuée d'agents autonomes. Hors scope.
- **`s15_agent_teams` (985 lignes), `s16_team_protocols` (882 lignes)** : coordination multi-agents (MessageBus file-based, state machines de protocole). Hors scope tant que le graphe reste mono-session. Forte redondance (le Task system est copié en tête de chaque fichier).
- **`s19_mcp_plugin`** : `MCPClient` est un **mock** (pas de vraie connexion serveur). Seul le naming convention `mcp__{server}__{tool}` est transposable. Le projet cible a déjà Context7 MCP branché.
- **`web/`** (Next.js 16 / React 19 / Tailwind) : site vitrine du cours (MDX, syntax highlighting, SVG animés framer-motion). TypeScript pur, non portable, non pertinent.
- **`docs/`** (36 fichiers Markdown, 12 leçons × 3 langues en/ja/zh) : documentation pédagogique narrative, pas de code.
- **Forte redondance** : le Task system (~80 lignes) est copié intégralement en tête de s12→s20. Préférer `s20_comprehensive/code.py` ou `agents/s_full.py` pour la version consolidée.

## Correspondance avec `plan_usine_logicielle.md`
- **P8 (Middlewares anti-crash)** : `s04_hooks` (architecture `HOOKS[event]` + `trigger_hooks`) = squelette de TOUS les middlewares (Sanitizer, Orphan Repair, LoopDetection) ; `s11_error_recovery` (`with_retry`, `RecoveryState`, fallback model) = middleware anti-crash ; `s08_context_compact` (préservation paires tool_use) = Orphan Repair. **C'est la priorité la mieux couverte.**
- **P9 (Reducers + Compaction)** : `s08_context_compact` (4 couches budget→snip→micro→auto) = équivalent Python de `context-compaction.ts` de qm, plus simple et testé.
- **P10 (Skill loading)** : `s07_skill_loading` (catalogue SYSTEM + `load_skill` on-demand) = blueprint quasi direct, à intégrer dans `skills_loader.py`.
- **P11 (Event stream)** : `s04_hooks` = l'event stream natif (events `UserPromptSubmit`/`PreToolUse`/`PostToolUse`/`Stop`), à exploiter comme couche d'observabilité.
- **P6 (Cycle de vie plan)** : `s12_task_system` (DAG `blockedBy` + `can_start`/`claim`/`complete`) + `s05_todo_write` (nag reminder + validation défensive) complètent `plan_store.py` (open-swe).
- **P0 (Spécialisation agents)** : `s06_subagent` (`spawn_subagent`, messages frais, cap 30 tours, pas de récursion) = patron d'instanciation de Coder/Tester spécialisés.
- **Lacunes assumées** (comblées par d'autres fiches) : P3 anti-loop (→ `crush`), P6 Judge/DuckDB claims (→ `open-swe`), P8-bis sandbox stricte (→ `qm`), P12 scopes utilisateurs (→ `qm`).
