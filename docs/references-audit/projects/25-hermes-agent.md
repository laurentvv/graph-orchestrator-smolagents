## Synthèse
Le projet `hermes-agent` est l'agent auto-amélioré de Nous Research : il apprend de ses sessions via une **boucle de curator + background review** (auto-création/amélioration de skills + mémoire), persiste chaque session dans **SQLite (FTS5 + WAL + triggers)**, délègue à des **subagents isolés**, planifie via **cron interne**, et exécute du code via **7 backends sandbox** (Docker, SSH, Modal, Daytona, Vercel Sandbox, Singularity, local).

Pour `graph-orchestrator-smolagents`, c'est un gisement **exceptionnellement riche** sur 5 axes orthogonaux, en grande partie du **Python pur portable** : (1) **compaction de trajectoire** (offline + live avec garde-fous persistés) pour P9, (2) **persistance SQLite FTS5** avec lineage parent/enfant et event-sourcing pour P11, (3) **système de skills agentskills.io** avec provenance, guard et AST audit pour P10, (4) **bibliothèque de sécurité** (threat patterns + dangerous commands + SSRF + path traversal) pour P3/P8, (5) **contrat de middleware** à 4 points d'extension pour P8. Secondairement : 7 backends sandbox (P1/P8-bis) et background review/error classifier (P6).

La valeur est **concentrée** et non diluée malgré la taille : les modules utiles sont autonomes (Python pur ou SQLite natif), sans dépendances exotiques. Les briques P9 et P11 sont presque directement réutilisables ; les modules sécurité sont copiables quasi tels quels.
**Note Globale : 🟢 Haute (9/10)** — un des dépôts les plus denses et les plus portables du dossier `references/`.

### Réserves
- **Pas d'event-sourcing DuckDB** : Hermes repose sur SQLite+WAL+FTS5. Pour le projet cible (DuckDB), il faudra transposer le pattern (indexer les events en DuckDB + réutiliser le design FTS5 SQLite pour le search, ou adopter l'extension FTS DuckDB).
- **Couplage aux providers LLM cloud** : adapters Anthropic/Codex/Gemini/Bedrock massifs (~1,5 Mo) — non portables (le projet cible utilise llama.cpp local). Les briques Top 8 n'en dépendent pas.
- **Prompts marqués "Claude Code" / "Codex"** : influence forte des system prompts externes — risque de "goût" Claude à adapter.
- **God-files** : `hermes_state.py` (9596 L), `agent/context_compressor.py` (6789 L), `cli.py` (877 ko). Le dépôt pousse à externaliser ("narrow waist" philosophy de `AGENTS.md`) mais reste concentré dans des fichiers géants — extraire les algorithmes, pas copier les modules entiers.
