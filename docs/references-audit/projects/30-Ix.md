# 30 - Ix

## En-tête
- **Nom** : Ix
- **Chemin** : `references/Ix/`
- **Type** : Framework de mémoire persistante et d'orchestration de contexte code (via graphe relationnel)
- **Langage principal** : TypeScript (Node.js)
- **Statistiques** : 256 fichiers (177 `.ts`, 16 `.md`, 14 `.sh`, 13 `.yml`, 12 `.json`)

## Synthèse
Ix est un outil en ligne de commande et un framework qui transforme un dépôt de code en un graphe requêtable (symbole, appels, imports) stocké dans une base de données (ArangoDB). Il permet aux agents IA (comme Claude ou SmolAgents) de naviguer dans le contexte avec une mémoire persistante plutôt que de dépendre de `grep` et de prompts saturés.

Pour le projet `graph-orchestrator-smolagents`, bien que le code de `Ix` soit en TypeScript, les concepts (chunking AST via tree-sitter, extraction de relations `CALLS`/`IMPORTS`/`CONTAINS`, optimisation des formats pour les LLMs, et le concept de *skills* injectables) sont extrêmement précieux. Les requêtes tree-sitter (`queries.ts`) sont même directement réutilisables dans notre implémentation Python. L'approche de formatage LLM (token-minimalisme) est aussi une pépite pour notre orchestration.

Note globale : 🟡 **Moyenne** (Portage algorithmique nécessaire depuis TS vers Python pour l'orchestrateur DuckDB, mais forte valeur conceptuelle et récupération directe possible des requêtes Tree-Sitter).
