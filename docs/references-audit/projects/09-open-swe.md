# 09 — open-swe

## En-tête
- **Nom** : open-swe (LangChain)
- **Chemin** : `references/open-swe/`
- **Type** : framework open-source pour internal coding agent (style Stripe Minions / Ramp Inspect / Coinbase Cloudbot)
- **Langage principal** : Python (agent + dashboard API, FastAPI) + TypeScript (UI TanStack Start/Vite)
- **Statistiques** : 447 fichiers pertinents (md/py/json/ts), ~7 MB ; 5 graphes LangGraph (`agent`, `reviewer`, `analyzer`, `chat`, `scheduler`)
- **Stack** : Deep Agents 0.7.0b2 + LangGraph 1.1.x + LangChain 1.3.x (et non DSPy/smolagents comme le projet cible)
- **Licence** : MIT

## Synthèse
Open SWE est un framework d'agent de coding interne complet, maintenu par LangChain et calqué sur l'architecture des agents internes de Stripe/Ramp/Coinbase. Les 7 piliers d'architecture (documentés dans `README.md`) sont : (1) **Harness** composé sur Deep Agents (pas un fork) ; (2) **Sandbox** cloud isolée et pluggable (Modal/Daytona/Runloop/E2B/LangSmith/local) ; (3) **Tools** curés (~15) ; (4) **Context Engineering** via `AGENTS.md` + contexte source (Linear/Slack) ; (5) **Orchestration** par subagents + middleware déterministe ; (6) **Invocation** Slack/Linear/GitHub ; (7) **Validation** prompt-driven.

Pour le projet cible (`graph-orchestrator-smolagents`, stack DSPy+smolagents), la **réutilisabilité la plus forte** se trouve dans trois zones : (a) le **module plan-review** (`plan_store.py` + `plan_api.py` + `tools/save_plan.py` + `middleware/plan_mode.py`) qui fournit un modèle complet de cycle de vie d'un plan avec commentaire, approbation, et gating d'outils — directement transposable pour structurer l'étape Architect du workflow cible ; (b) le **module review** (`findings.py` + `pr_diff.py` + `review_styles.py`) qui offre un schéma de findings riche et un diff de PR multi-fichiers — utile pour le Judge ; (c) le **workflow d'approval** générique (`workflow_approval.py`) pour les pushes de fichiers sensibles.

La réutilisabilité est **moyenne au niveau global** parce que la stack (Deep Agents/LangGraph/LangGraph Store pour la persistance) diffère fortement de DSPy/smolagents + DuckDB, et que le couplage à LangGraph SDK est omniprésent dans le code du dashboard. Les patterns et les schémas sont très transférables ; le code lui-même nécessite une adaptation.

## Exclusions conscientes
- **UI TypeScript** (`ui/`, TanStack Start + Vite, package `open-swe-dashboard`) : chat UI, pages admin, picker de repos, page de revue de plan. Non pertinent pour le projet cible (pas d'UI web).
- **Backend sandbox cloud** (`agent/integrations/daytona.py`, `modal.py`, `runloop.py`, `e2b.py`, `langsmith.py`) : providers spécifiques basés sur `SandboxBackendProtocol` de Deep Agents.
- **Stack Deep Agents / LangGraph** (`deepagents`, `langgraph`, `langchain>=1.3.9`, `langgraph-sdk`, LangGraph Store pour persistance) : fondamentalement différente de DSPy + smolagents + DuckDB.
- **Intégrations triggering Slack/Linear/GitHub** (`agent/utils/slack.py` 45 KB, `agent/utils/linear.py`, `agent/webapp.py`, webhooks).
- **MCP servers** (`datadog_mcp`, `notion_mcp`, `corridor_mcp`, `stagehand_browser`).
- **OAuth GitHub/Slack dashboard** (`agent/dashboard/oauth.py`, `slack_oauth.py`, `notion_oauth.py`, `agent/encryption.py`, `agent/utils/auth.py` 20 KB).
- **LangSmith specifics** : tracing project routing, LLM Gateway, sandbox snapshots, proxy GitHub.
